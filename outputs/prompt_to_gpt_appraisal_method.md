# GPTへの質問プロンプト（走力・肩力を中心に、査定手順の実体を聞く）

> 使い方: 以下の「---」から下をそのままコピーしてGPTへ送る。
> 可能なら `docs/satei_handoff/` の12ファイル（特に 02・04・06）を添付する。

---

あなたが以前このプロジェクト（パワプロ風ペナントの選手査定）で作った仕様を、いま実装に移しています。実装した結果、**走力と肩力だけが明らかに低く出る**という問題が起きました。原因を切り分けたいので、当時あなたが実際にどう決めていたかを教えてください。

## いま起きていること

実在選手の査定で、たとえば鈴木誠也（広島時代）がこうなります。

- 走力 E45（100段階。50が平均、15が標準偏差1つ分）
- 肩力 D60

オーナーの認識では **走力はC〜B、肩力は80後半〜90前半**です。パワーやミートは実感と合っているのに、走力と肩力だけが合いません。

## 実装が使っているデータ

日本の公開データだけで作りました。

- プロEYE球（1936-2025）: 打撃・投手・守備の基礎成績。守備は 試合数・守備率・刺殺・**補殺**・失策・併殺・捕逸
- NPB Basement（2020-2026）: UBR、wSB、TZR、RngR、DPR、**ARM**、ErrR、フレーミング、ブロッキング、打球性質（ゴロ/ライナー/フライ%）
- NF3（2023-2025、選手ページ2,098枚）: 月別・対左右・ランナー別・球場別・Home/Visitor・Day/Night・打撃内容

走力は「三塁打率・併殺回避率・UBR」の3つをzスコア化して平均、肩力は「ARM（送球で防いだ失点）と補殺率」を合成、いずれも前後3年で均しています。

## 実装側で分かっている限界

肩について、**強肩の選手ほど走者が走ってこないので、刺す機会そのものが減る**という構造を実測で確認しました。鈴木誠也のARM（1000イニングあたり）は2021年が4.99で右翼99人中5位ですが、**2020年は0.01でちょうどリーグ平均**です。同じ肩なのに年で暴れます。補殺を足しても、合成後は「平均より1標準偏差上」が天井で、それ以上は出せませんでした。

## 聞きたいこと

### Q1. 走力をどう決めていたか（最重要）

仕様 `04_RUNNING_DEFENSE_CATCHER.md` §1.2 はデータを3階層に分けています。

- 第1階層: Sprint Speed / 一塁到達タイム / 走塁時最高速度 / 30m・50m走 / Home-to-first / 外野での追走速度計測
- 第2階層: 公式スカウティング / 代走起用 / 映像計測 / Statcast Baserunning Run Value 等
- 第3階層（補助）: 三塁打率 / 内野安打率 / 併殺回避 / BsR・UBR / 追加進塁率

**当時あなたは、実際にどの階層のどのデータを使って走力の数字を出していましたか。**

- 第1・第2階層のデータを、日本のどの情報源から取っていましたか（選手名鑑の50m走、スポーツ紙、球団公式、映像など、具体名で）
- 情報源が無い選手はどう埋めていましたか
- 第3階層だけで決めた選手はいましたか。いたなら、その場合の変換式（zスコアからランクへの写像）を教えてください
- 3つ以上の材料を混ぜる時の**重み**はどう決めていましたか（等重み／材料ごとに変える／信頼度で変える）

### Q2. 肩力をどう決めていたか（最重要）

仕様 §4.3 は「純粋速度・遠投＝肩力／精度＝送球得能」、§6 は外野肩の材料として「送球速度・**進塁抑止**・Arm Runs」を挙げ、「**補殺数だけで肩Sにしない**」と書いています。

- **送球速度・遠投の数値を、日本のどの情報源から取っていましたか**（選手名鑑の遠投距離、球団発表、計測イベントなど）
- 「**進塁抑止**」はどう数値化していましたか。日本の公開データで「走者が進塁を試みなかった回数」は取れないはずですが、代替をどう作っていましたか
- 鈴木誠也を80後半〜90前半に置いた時、**具体的に何の数字を根拠にしていましたか**
- 内野手（一塁・二塁・三塁・遊撃）の肩はどう決めていましたか。日本には内野手の送球速度の公開データがありません

### Q3. 「廃版」になった過去の値との関係

`06_CARP_CASE_STUDY_AUDIT.md` には、過去の査定について厳しい自己批判が並んでいます。

- 田中広輔2017:「35盗塁を走力Aへ直結」「32二塁打・5三塁打を『脚とギャップ』と根拠なく断定」
- 菊池涼介2016:「S98/A86等の値はゲーム校正なし」「守備範囲を走力へ二重計上」
- 鈴木誠也2018:「過去の値はM76→M73等と揺れたが**全て廃版**」

一方で、オーナーの記憶では**当時の値の方が実感に合っていた**とのことです。この食い違いをどう理解すればよいですか。

- 廃版にしたのは**値**ですか、それとも**根拠の書き方**ですか
- 「根拠が弱いが実感に合う値」と「根拠は固いが実感からずれる値」のどちらを採るべきという設計思想でしたか
- 廃版後、走力・肩力について**代わりの決め方**は確定していましたか。確定していたなら、それはどの文書のどこに書かれていますか

### Q4. これから取るべきデータ

実装側で新たに取りに行くとしたら、どこから何を取るのが最も効きますか。優先順に3つ挙げてください。日本語圏で実際に入手できるものに限定してください（選手名鑑の身体データ、球団公式のプロフィール、計測イベントの記録、映像からの計測など）。あわせて、それぞれの取得可否・網羅年数・ライセンス上の注意も分かる範囲で教えてください。

### Q5. 他の能力についても同じ確認

走力・肩力以外（弾道・ミート・パワー・守備力・捕球、および得能）についても、**第1〜2階層に相当する情報を使っていた項目があれば**教えてください。実装は全項目を公開統計だけで作っているので、同じ取りこぼしが他にもあるか知りたいです。

## 回答の形式

各項目について、**「使ったデータ」→「変換の手順」→「鈴木誠也での実際の当てはめ」**の順で、具体的な数字を添えて書いてください。抽象的な原則ではなく、**再実装できる粒度**でお願いします。

情報源が記憶にない・当時から曖昧だった項目については、**そう明記してください**。埋めずに空白のまま返してもらう方が、こちらとしては安全です。
