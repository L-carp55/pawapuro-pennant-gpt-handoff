# Phase 3a レポート — 能力値と打席結果の相互変換

## 1. 何を作ったか

査定（成績→能力値）とエンジン（能力値→成績）を、**同じ変換の表裏**として実装した。設計書 §1 の核心部分。

| ファイル | 役割 |
|---|---|
| `configs/ratings.json` | 能力値スケールの定義。Sol仕様のアンカー値をそのまま設定に置く（コードに数値を埋めない） |
| `src/ratings/scale.mjs` | アンカー表の双方向補間、分布ベースの能力値変換 |
| `src/ratings/from_rates.mjs` | 査定: 実成績 → 能力値 |
| `src/ratings/to_rates.mjs` | エンジン: 能力値 → 打席結果の確率ベクトル |

## 2. 循環を作らない設計

打席結果を決める4要素を、それぞれ独立した能力に割り当てた。

| 能力 | 決めるもの | 根拠 |
|---|---|---|
| ミート | 打率 | Sol仕様 03 §4.4 のアンカー（.180→19 … .370→94） |
| パワー | 本塁打率（500打席相当） | Sol仕様 03 §5.5 のアンカー（10本→60 … 70本→110） |
| コンタクト | 三振率 | 実データの対数分布からzスコア変換 |
| 選球眼 | 四球率 | 同上 |

インプレー安打率（BABIP相当）は独立の能力にせず、**打率という制約から逆算**する。これにより「ミートが三振率にもBABIPにも効く」という循環が生じず、往復が数学的に保証される。

## 3. 検証: 往復テスト

2024年・200打席以上の**119人**で、実成績 → 能力値 → 確率ベクトル → 実成績 の往復を実行。

| 項目 | 往復誤差（最大） |
|---|---|
| ミート | **0.00** |
| パワー | **0.00** |
| コンタクト | **0.00** |
| 選球眼 | **0.00** |
| 打率 | 1.87e-4（丸め由来） |
| 本塁打率 | 1.36e-4（同上） |

**完全可逆**。査定とエンジンが同一の変換であることが実証された。

### 途中で見つけた不具合

初回実行で119人全員が変換不能になった。原因は、アンカー表が `[観測値, 能力値]` の順で定義されているのに、**査定側とエンジン側で補間の向きを取り違えていた**（査定は順方向`interp`、エンジンは逆方向`interpInverse`が正しい）。修正後に往復誤差0を達成。

コンタクト・選球眼の中央値が約50で設計通り。ミート・パワーはSol仕様アンカーに従うため、中央値が50付近になるのは結果。

## 5. Phase 3a の合格判定

- ✅ 往復誤差1.0未満（実績0.00）
- ✅ アンカーは設定ファイル。コードに数値を埋めていない
- ✅ 実選手119人で実行し誤差分布を数値提示
- ✅ 循環のない設計で可逆性を構造的に保証

## 6. 次段階への申し送り（既知の課題）

1. **パワーの下限がクリップしている** — 最小25.0に張り付く。本塁打0本の選手が全員同じ値になるため。Sol仕様 §6.4「本塁打だけで決めない」の通り、**ISO/SLG/二塁打率の併用が必要**（下限アンカー[0,25]自体もSol仕様に無い暫定値）
2. **選球眼の下限が1.0に到達** — zスコアの spread=15 が狭い可能性。実分布を見て調整する
3. **ミートの上限が68.9** — 2024年の最高打率が.316程度のため。アンカー上端（.365→90）に届く選手は稀で、これ自体は妥当
4. **未着手**: 弾道・走力・肩・守備力・捕球の査定（Phase 3c）、環境補正と小サンプル縮小＝経験ベイズ（Phase 3b）、特殊能力（チャンス・対左）
5. **投手の能力化も未着手** — 現在エンジンは投手の確率ベクトルを直接使っている
