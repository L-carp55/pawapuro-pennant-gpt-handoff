## 2. 中心の問いへの回答

### 2.1 文脈階層と得能反映は、同じ機構か別の機構か

**結論: 責務は別、数値計算は一つにします。**

- A/B/C階層は、どの観測統計を基準にできるかを決める**証拠選択機構**
- 得能反映は、選択された観測統計を再現する基礎能力をゲームエンジンから逆算する機構
- ただし、「基準統計を能力化した後、チャンス分を引き、さらに対左分を引く」という**独立した加減算処理は禁止**
- 実装上は、A/B/Cが返す「文脈範囲」を入力として、得能込み性能から基礎能力を**一度だけ同時逆算**します

つまり、次のような関数は作りません。

```
M3 = M2
M3 -= chance_points
M3 -= vs_left_points
```

代わりに、次の一つだけを用意します。

```
M3 = invert_effective_performance(
    target = M2,
    assigned_abilities,
    observed_context_scope,
    feasible_context_exposures
)
```

第2層は「平均的な得能を含んだ能力」、第3層は「当該選手の得能との差を反映した基礎能力」と定義されているため、第2層を固定された実効性能目標として、第3層を逆算する構造が適合します。

**文脈階層ごとの扱い**

| 階層 | 基準にする打席 | チャンスをM3逆算に使うか | 対左をM3逆算に使うか |
|---|---|---|---|
| A | 対右×非得点圏 | 使わない | 使わない |
| B | 対右の全打席 | 条件付きで使う | 使わない |
| C | 全打席 | 条件付きで使う | 条件付きで使う |

**階層A**: 対右かつ非得点圏では、チャンスも対左も発動対象外。この基準から推定するミートには、チャンス・対左の調整を一切かけない。これらは第4層の実効能力で、対応する打席に入ったときだけ発動する。ただし、ファイル上では交差セルが取得できないため、現在のデータ環境ではAには到達できない。

**階層B**: 対右打席だけを基準にするため、対左得能の影響は基準統計から既に除外されている。したがって、対左得能を理由にさらに基礎ミートを上下させてはいけない。**「字義通り実装すると対左の得能調整をする余地がなくなる」は、設計上の欠陥ではなく、二重計上を避けるための正しい帰結**。一方、対右打席には得点圏と非得点圏の両方が含まれるため、チャンス得能の影響は残っている。しかし、「対右かつ得点圏」の打数が不明なので、常に一意な補正ができるわけではない。

**階層C**: 総合打率にはチャンスと対左の両方が含まれる。ただし、Cは「総合のみ」であるため、それぞれの発動打席数すら取得できない。非平均的なチャンス・対左得能がある選手について、総合打率だけから一意の基礎ミートを求めることは原則としてできない。**したがってCは、単純に「両方の得能点を引く階層」ではなく、多くの場合に第3層が識別不能になる階層として扱うべき**。

### 2.2 チャンスと対左の打席重複をどう扱うか

**基本原則**: 打席を次の4セルに分ける。

1. 右投手 × 非得点圏
2. 右投手 × 得点圏
3. 左投手 × 非得点圏
4. 左投手 × 得点圏

チャンスと対左を別々に順番に補正するのではなく、4セルをゲームエンジンで同時に評価する。特に「左投手×得点圏」では、チャンスと対左が同時に発動するため、「対左の効果 + チャンスの効果」と機械的に足してはいけない。エンジンが実際に行う合成結果をそのまま使う。

**交差打数の取り得る範囲**: 全打数をN、対左打数をN_L、得点圏打数をN_C、左投手×得点圏打数をxとすると、観測された周辺値と矛盾しない範囲は次:

```
max(0, N_L + N_C - N) ≤ x ≤ min(N_L, N_C)
```

各セルの打数: N_{L,C}=x, N_{L,N}=N_L-x, N_{R,C}=N_C-x, N_{R,N}=N-N_L-N_C+x

**ここから一つのxを選んで交差セルを作ることはしない。取り得るすべてのxを残したまま、基礎能力の取り得る範囲を計算する。**

「左右の比率と得点圏比率は独立」と仮定して x = N_L×N_C/N のように置くことも**禁止**する。これは観測されていない交差セルをモデル仮定で一点化する行為であり、**禁止された交差値の捏造と実質的に同じ**。

**重なりを無視してよい条件**（次のいずれか）:
1. 基準統計が片方の文脈を完全に除外している（例: 階層Bの対右打率では対左得能の発動打席がゼロ）
2. 片方の得能効果が同成績帯平均と同じ（個別差分がゼロならその軸の重なりは基礎能力に影響しない）
3. エンジン上、両得能の相互作用がないことを実測確認できた（`I(b) = g_{L,C}(b) - g_{L,N}(b) - g_{R,C}(b) + g_{R,N}(b)` が対象能力範囲で0が成立し、集計も打数加重で線形なら、総合性能は対左割合と得点圏割合だけで計算でき交差比率は不要。この判定に任意の係数は使わず、エンジンの実測結果と既存の数値精度だけを使う）
4. 交差打数の全候補で最終的なM3が同一になる（取り得るすべてのxで逆算し、既存保存精度において同じ能力値になるなら一点化できる）

**重なりを無視してはいけない条件**（次が同時に成立）:
- チャンスと対左の両方に、同成績帯平均からの差がある
- 両方が基準統計の対象打席に含まれる
- 交差打席数が観測できない
- エンジン上の相互作用がゼロであると確認できない
- 交差打席数の候補によって逆算能力が変わる

この場合は、単一の能力値ではなく**範囲を返すか、識別不能とする**。

### 2.3 本塁打・パワーもミートと同じ方法でよいか

**結論: 外側の設計は同じ、測定可否の判定は別にするべき。**

共通する部分:
- 得能ごとの点数を直接加減しない
- ゲームエンジンの得能効果を使って基礎能力を一度だけ逆算する
- チャンスと対左が重なる場合は同時評価する
- 交差打席が不明なら、可能な曝露範囲全体で能力範囲を出す

一方、**パワーについてはミートのA/B/C階層をそのまま移植してはいけない**。パワー側には対応するTier仕様が明記されていないため。

**パワー側の基準**: 環境補正・小サンプル縮小 → 500打席相当本塁打数 → 既存の較正済みパワー変換関数、を第1層・第2層の基準にする。その後、割り当て済みの対左パワー得能等をゲームエンジンに入れ、500打席相当の目標本塁打数を再現する基礎パワーを逆算する。

**対左本塁打の生値から直接調整してはいけない**。ファイルでは、総本塁打が20〜40本程度、対左に限定すると数本〜十数本であるとされている。したがって「対左本塁打率が高い→基礎パワーを○点下げる」という変換は認められない。

認められるのは次のいずれかだけ:
1. 得能効果がゲームエンジン内で既に較正済みであり、その効果を逆算に使用する
2. 対左本塁打差が、既存の小サンプル縮小・測定誤差判定を通過している実測データから効果量を新たに較正する

**既存の縮小処理が点推定しか返さず、「偶然のばらつきに埋もれているか」を判定できない場合、単シーズンの対左本塁打差を基礎パワーに反映する設計は、現時点では採用できません。** 新しい最低打数、信頼水準、補正倍率をここで置くことは、係数新設に当たるため行わない。

### 2.4 受け入れ基準

受け入れを3段階に分ける。

**A. 設計構造の受け入れ**（次をすべて満たしたらアーキテクチャとして採用可能）:
- A/B/Cモジュールは能力点を変更せず、「基準統計・文脈範囲・曝露制約」だけを返す
- 第3層を生成する数値処理が一つの逆算関数だけである
- チャンス用・対左用の独立した加減算関数が存在しない
- 得能の発動文脈と基準統計の共通部分だけが逆算に入る
- 同じ観測事実の利用先を調整台帳で一意に追跡できる
- 数値変換は既存の較正済み関数、エンジン実測、観測打数だけで構成される

これは、係数ハードコード禁止と二重計上禁止に直接対応する。

**B. 個別選手の数値採用**（個別のM3/P3を一点で確定してよい条件）:
1. 基準統計が実測値であり、交差値を合成していない
2. 使用する得能効果がエンジン上で較正済み
3. 基礎能力から実効性能への写像が、対象範囲で逆算可能
4. 観測された周辺打数と整合する曝露候補集合が空でない
5. すべての曝露候補から得られる能力値が、既存の保存精度で同一
6. 既存の小サンプル処理を含めても、能力値が一意に決まる
7. 逆算後に同じエンジンへ戻すと、第2層の目標性能を再現する

5または6を満たさない場合は、点ではなく範囲を保存する。範囲を保存できない仕様なら、その選手は査定不能または暫定とする。

**C. 最終採用**: 最終的には、12球団×143試合のシミュレーションで、リーグ全体の打率・本塁打等の分布が実データと一致することが必要。ファイルで示された最終基準もこれ。さらに内部診断として、階層A/B/C別・チャンス青赤別・対左青赤別の残差の偏り、得能が多い選手だけ一律に基礎能力が低くなる等の系統誤差がないことを確認する。

**外部ゲームの能力値との一致は、参考比較に留め、採否条件にはしません。**

## 3. 提案する設計

### 3.1 数式

能力種別を q∈{M,P} とする。

**第1層**: 選択された実測統計に、既存の環境補正・サンプル縮小を適用。`z_{i,q,J} = C_q(observed_statistic_{i,J})`（J: 基準統計の文脈範囲、C_q: 既存の補正処理。新規係数は置かない）

**第2層**: 既存の較正済み変換関数を使用。`A^{(2)}_{i,q} = F_q(z_{i,q,J})`（ミート: 既存の打率→ミート変換／パワー: 既存の500打席相当本塁打数→パワー変換）

**第3層**: ゲームエンジンで、基礎能力b・割り当て得能S_i・文脈曝露wから統計を生成: `SimStat_{q,J}(b, S_i, w)`。これを同じ既存関数で能力換算: `EffEq_{q,J}(b,S_i,w) = F_q(SimStat_{q,J}(b,S_i,w))`。第3層候補集合は:

```
B^{(3)}_{i,q} = { b∈[1,130] | ∃w∈W_{i,J}, EffEq_{q,J}(b,S_i,w) = A^{(2)}_{i,q} }
```

既存のサンプル処理が目標値の許容範囲を返す場合は、等号をその許容範囲への包含に置き換える。

**第4層**: `A^{(4)}_{i,q} = Engine(B^{(3)}_{i,q}, S_i, actual_game_context)`。第4層を計算した後、チャンスや対左を理由に第3層を再調整してはいけない。

### 3.2 能力の方向は逆算から自動的に生じる

固定された第2層目標に対して:
- 青得能が平均より強ければ、同じ基礎能力で実効性能が高くなるため、逆算される基礎能力は**低くなる**
- 赤得能が平均より強ければ、同じ基礎能力で実効性能が低くなるため、逆算される基礎能力は**高くなる**

このため、**青得能1個につき何点という係数は不要**。ファイルで指定された方向性を、エンジン逆算だけで実現できる。

### 3.3 ミートのTier別データフロー

```
実測H/AB
  ↓
Tier選択
  ↓
基準統計 + context_scope + 曝露制約
  ↓
既存の環境補正・サンプル縮小
  ↓
第1層 補正成績
  ↓
既存のF_M
  ↓
第2層 平均得能込み基準
  ↓
ゲームエンジンによる単一の同時逆算
  ↓
第3層 個別査定能力 または能力範囲
```

**Tier A**: `scope = {右投手 × 非得点圏}`、`chance_active = false`、`vs_left_active = false`。`M^{(3)} = F_M(AVG^{corrected}_{R,nonRISP})`。チャンス・対左以外の得能がこの文脈でも発動する場合は、それだけ同じ逆算機構に含める。

**Tier B**: `scope = {右投手 × 全状況}`、`vs_left_active = false`、`chance_active = true`。対右打数をN_R、得点圏打数をN_C、総打数をN、対右×得点圏打数をyとすると `max(0,N_R+N_C-N) ≤ y ≤ min(N_R,N_C)`。すべてのyについてM3を逆算する（全候補で同じM3なら一点採用、候補ごとに異なれば範囲保存、範囲保存不可なら識別不能）。対左得能は逆算には入れないが、第4層では左投手打席に通常どおり発動させる。

**Tier C**: `scope = {全打席}`、`chance_active = unknown exposure`、`vs_left_active = unknown exposure`。総合H/ABしかないなら、チャンス・対左の発動割合を観測できない。したがって次の場合を除き一点査定は行わない: 両得能の個別差分がゼロ／エンジン上、文脈割合に依存しないことが実測済み／別途、実測された文脈曝露が入力されている。

### 3.4 実装上の二重計上防止

```
AnchorResult:
    statistic_type
    observed_value
    corrected_value
    tier
    context_scope
    feasible_exposure_set
    source_fact_ids

AbilityEffect:
    ability_id
    affected_statistic
    trigger_context
    calibrated_engine_effect_id
```

逆算時には `active_context = context_scope ∩ trigger_context` を強制する。積集合が空なら、その得能は第3層逆算に一切寄与できない。

第3層を生成できる関数を次の一つに限定する: `infer_individual_base(anchor, abilities, engine)`

以下の関数は設けない:
```
subtract_chance_effect()
subtract_vs_left_effect()
adjust_for_blue_ability_count()
adjust_for_red_ability_count()
```

調整台帳には、各観測事実について `performance_target` / `ability_assignment_evidence` / `exposure_count` / `validation_only` のどこで使ったかを記録する。**同じ成績差を「得能付与」と「追加の基礎能力補正」の両方へ独立入力することは禁止する。** 完全な中立統計を使った後に得能を理由としてさらに下げない、という正本仕様にも対応する。

## 4. この設計が使えない／使うべきでないケース

| 検出コード | 条件 | 処理 |
|---|---|---|
| CROSS_CELL_UNOBSERVED | 必要な交差曝露がなく、候補によってM3/P3が変わる | 範囲または識別不能 |
| TIER_C_CONTEXT_UNKNOWN | 総合成績しかなく、文脈得能に個別差がある | 一点査定禁止 |
| RARE_EVENT_UNMEASURABLE | 対左本塁打差が既存のサンプル処理で測定可能と確認できない | パワー差分を反映しない |
| ABILITY_EFFECT_UNCALIBRATED | 得能のゲーム内効果が較正されていない | 数値逆算禁止 |
| NON_INVERTIBLE | 同じ実効性能を作る基礎能力が複数ある | 全解集合を保持 |
| NO_SOLUTION | 1〜130の範囲で目標性能を再現できない | クランプせず仕様不整合として停止 |
| DUPLICATE_EVIDENCE | 同じ観測差を複数の独立調整で使っている | 当該査定を無効化 |
| SYNTHETIC_INTERSECTION | 独立仮定や任意係数で交差値を一点生成している | 当該処理を禁止 |
| CONTEXT_MAP_MISMATCH | 既存の変換関数が対象文脈の統計に較正されていない | 新係数を作らず未対応扱い |
| DEPENDENT_ABILITY_ESTIMATE | 得能自体を同じ成績データから推定しているが、共同推定・不確実性管理がない | 第3層を暫定扱い |

特に現在のミートデータでは階層Aに到達できないため、階層Bでチャンス差が大きい選手と、階層Cしかない選手は、事前に識別不能となり得るクラスである。

## 5. 撤回条件

### 5.1 個別選手について撤回する条件

次のいずれかが観測されたら、その選手の一点査定を撤回して範囲または未確定に戻す:
- 交差曝露の候補によって能力値が変わる
- 基礎能力から実効能力への逆算解が複数ある
- 1〜130内に解が存在しない
- 得能効果を外す順序によって結果が変わる
- 同じ観測成績が台帳上で二重利用されている
- 既存の小サンプル処理を通すと得能差の方向や有無が維持されない
- 実測された交差データが後から入手され、現在の推定範囲外になる

### 5.2 設計全体を撤回する条件

次のいずれかが確認されたら、この設計自体を捨てるか再設計する:
- **ラウンドトリップ不成立**: 第3層＋得能をエンジンへ戻しても、第2層の目標性能を再現できない
- **得能別の系統誤差**: チャンス青選手だけ過大、対左赤選手だけ過小など、得能群ごとに残差が偏る
- **Tier別の系統誤差**: BやCだけ能力が一方向にずれる
- **任意係数なしでは成立しない**: 交差値の独立仮定、固定補正点、手動倍率を追加しなければ再現できない
- **リーグ分布が一致しない**: 12球団×143試合で、リーグ全体の打率・本塁打分布が実データから系統的に外れる
- **局所一致と全体一致が両立しない**: 個別選手の第2層は再現できても、リーグ全体では平均や分布が崩れる

最終的な採否はエンジン検証後になる。現時点で採用できるのは、文脈階層を得能補正点として使わず、文脈付きの単一逆算問題として扱う設計構造までである。リーグ分布検証が未実施である以上、数値方式を最終確定とは扱わない。
