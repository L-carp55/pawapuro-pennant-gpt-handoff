# Cross-game comparison

## Reading rule

この比較は、PowerPro・Prospi・MLB The Showの機能数や人気順を決めるものではない。公開されたプレイヤー発言・記事・公式説明を、同じ意味の論点へ揃えたものだが、言語・プラットフォーム・版・プレイ方法に偏りがある。詳細は [cross_game_comparison.tsv](./cross_game_comparison.tsv)、個別証拠は [evidence_index.tsv](./evidence_index.tsv) を正本とする。

## Shared signal

3作品に共通する最も強い信号は、**CPUを強くしてほしい**ではなく、**CPUが行ったことを後から理解でき、長期世界が動き続けてほしい**である。

- PowerProでは、外国人放出・ドラフト偏重・資金不足・能力画面の往復が、組織行動の理由不足として現れる。
- Prospiでは、記録・殿堂・意外なCPU選手が長期の魅力になる一方、年数後の獲得・放出・候補生成停止疑いがある。
- MLB The Showでは、球団別トレード評価・反提案・Trade Hub・Streamlinedが公式に進んだ一方、コミュニティはトレード過剰と硬直、打順・ブルペン、成長回帰を逆方向から訴える。

## What should not be averaged

1. **トレード件数** — 多すぎるという声と、少なすぎる・拒否されるという声が同時にある。設定、球団、年数、契約、情報、プレイ方針を保存し、件数の平均にしない。
2. **リアルさとテンポ** — 長い演出・確認・候補一覧は情報を増やすが、周回テンポを壊す。意味のある結果を残すことと、操作を短くすることを分ける。
3. **能力と成績** — 意外な選手の活躍は物語として価値があるが、能力値の誤りの証明ではない。絶対能力、時代相対表示、球団評価、観測成績を分離する。
4. **隣接モード** — myBALLPARKのテンポ・自動化要望はUI設計の参考にはなるが、classic Prospi PennantのCPU市場の証拠にはしない。
5. **不具合と設計** — 進行停止、表示不整合、保存喪失は重要だが、PWの世界モデル要件へ直結させず、版別QAに送る。

## Priority reading for Pennant World

### P0: 理由が返る組織行動

PW-004/006/007-PW-014/124-PW-140/236の方向は、今回の横断信号とよく整合する。球団が選手を取る・放出する・残す・待つ時、評価、契約、役割、ファーム、競争窓、本人意思、見えている情報を短い理由として返すことが、CPUの強さより重要である。

### P0: 長期セーブの活動量と復旧

年数を進めても、候補生成、移籍、昇降格、成長、記録、制度が止まらないこと。止まった場合に、いつ・どの処理で・何が止まったかを追えること。これはPW-001-PW-004とPW-187-PW-229をつなぐ品質条件である。

### P0: 委任と可視化の両立

PW-010-PW-014の単純操作は、深い内部を隠すことではない。自動化した後に、重要な変更、理由、不確実性、復旧点を短く確認できることが必要である。

### P1: 未仕様領域へ戻す

OD-01（配置AI）、OD-04（特殊能力ライフサイクル）、OD-07（ロースター権利）、OD-12（賞・殿堂）、OD-13（経済）、OD-15（戦略メタ）、OD-16（情報可視性）、OD-17（身体成熟）が、今回の証拠から次の候補として浮かぶ。ただし、証拠が薄い領域は候補のまま止める。

## Design challenge

単純化すると、各作品の不満は「もっと機能を」という要求に見える。しかし、証拠の中心は機能数ではなく、次の一文に集約される。

> 長期世界の変化を任せられ、必要な時だけ短く介入でき、後から理由と歴史を追えること。

この条件を満たさない機能追加は、操作量・待ち時間・情報の断片化だけを増やす。逆に、既存のPW設計がこの条件を満たせるなら、今回の新候補の多くは追加IDではなく、既存要件の可視化・QA・長期安定性の検証として扱える。
