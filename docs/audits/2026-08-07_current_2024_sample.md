計算ログ:

```text
統計由来の複数年走力（scale前） = 72.598
speed_z_final                    = +1.5065z
使用年度                         = 2021, 2022, 2023, 2024
外部直接計測                     = なし

```

したがって「源田だけに未来データが入った」「直接計測の誤上書き」ではない。

## 現行pipelineそのものによる走力目盛り監査

2024年・150打席以上・旧パワプロ参照値を持つ142人を、単年 `speedComponents` ではなく現在の `appraiseCard` 経路で再計測した。
KONAMI値は正解として採用するためではなく、**現行の scale_calibration がそもそもその参照分布を目的に作られていたので、較正対象がずれていないか検査するためだけ**に使った。

```text
n=142
現行素点      mean=50.456 sd=9.150
参照分布      mean=64.190 sd=14.848
相関          r=0.8332

現行旧較正    slope=1.381113 intercept=-4.330107
現行pipelineの中心幅だけ合わせると
              slope=1.622595 intercept=-17.679969

RMSE
素点          16.322
旧較正         8.297
中心幅再fit    8.576
```

重要: 単純に「古い較正だから再fit」すると源田はさらに約100.1になる。つまり問題は係数更新だけではない。
現在の方式は、素走力の上位を広い参照分布へ引き伸ばすこと自体が目的になっている。

例:

```text
源田  raw72.6 -> 旧較正95.9 / 参照80
周東  raw70.5 -> 旧較正93.1 / 参照96
近本  raw63.9 -> 旧較正83.9 / 参照86
```

源田だけ個別補正するのは不可。次に見直すべきは「走力100段階の目盛りを何に対して定義するか」。
最上位方針は自作エンジン整合なので、最終的にはKONAMI分布合わせではなく、直接計測とエンジン内の走力→到達時間/進塁性能の応答で尺度を定義するのが筋。

## peak年度選定の現在地

2020年以降の年度候補にはUBRと位置別守備得点を接続済み。守備得点の定義:

```text
1B/2B/3B/SS = RngR + ErrR + DPR
LF/CF/RF    = RngR + ErrR + ARM
C           = ErrR + ARM + Framing + Blocking
DH          = 0
```

2020+はPA>=200の698/699選手年で走塁+守備が揃う。一方2019年以前は高度指標が無いため0/1679。
欠損を0扱いしない原則から、全キャリアの自動`peak`はCLIで停止を継続する。

また旧未較正ポジション補正は本番総合点からデフォルト除外済み。監査では170人中23人(13.5%)のピーク年を変え、絶対値平均6.02点と実測守備得点6.03点に匹敵していたため。

## 次の判断ポイント

この8人をオーナーが目視し、特に以下を確認する。

1. 源田95.9 / 周東93.1 / 近本83.9という走力上位の間隔がゲーム内尺度として妥当か。
2. 捕球が多くの選手で50台に寄る現在の強い縮小を維持するか。
3. 近本・源田の守備力が50台になる「走力で説明できる範囲を引く」設計を維持するか。
4. 内野肩の推定値は直接計測が整うまで未査定へ戻すか。

個別値を手で直す前に、上記の尺度・対象概念を先に裁定する。
