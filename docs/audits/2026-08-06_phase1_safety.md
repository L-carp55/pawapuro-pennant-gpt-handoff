# 査定 Phase 1 安全修正

## 結論

誤った能力カードを増やすより先に、次の2経路を停止・修理した。

1. 年度カードへ対象年より後の走力・肩力データが混ざる経路
2. 走塁・守備得点が未接続なのに「総合ピーク」「総合全盛期」として自動選定する経路

この変更は査定式を完成させるものではない。誤った前提でカードが生成されることを防ぐ安全ゲートである。

## 修正内容

### 1. 未来年度の情報を遮断

`src/cards/durable_estimate.mjs`

変更前:

```text
対象年-3 ～ 対象年+3
```

変更後:

```text
対象年-3 ～ 対象年
```

対象:

- 走力の複数年推定
- ARMの複数年推定
- 外野手・捕手の補殺による肩力推定

例として2024年カードでは、2025年以降のデータを使わない。

### 2. 総合ピーク選定をフェイルファスト化

`src/cards/peak_year.mjs`

`mode=total`では、全候補年度に次が必要になった。

- `runRuns`
- `fldRuns`

どちらかが未接続なら例外を出し、打撃中心の年度を「総合ピーク」と誤表示しない。

`mode=batting`は明示的に指定した場合のみ、走守なしで利用できる。

### 3. 全盛期の総合窓選定をフェイルファスト化

`src/cards/prime_composite.mjs`

`mode=total`で走塁・守備得点が無い場合、全盛期窓を選ばない。

なお、次の問題はまだ未修理であるため、primeカード自体を再開しない。

- 打撃は複数年合成、守備・走塁・弾道等は窓末年という期間混在
- 合成前に基準環境へ補正した成績を、通常査定で再補正する可能性
- 分割成績・得能の合成方法が未定義

### 4. CLIから危険な自動生成を停止

- `scripts/build_card.mjs`
- `scripts/build_cards_batch.mjs`

`peak`と`prime`を拒否し、個別カードは4桁年度を明示して生成する。

```bash
node scripts/build_card.mjs 村上 2024
```

## 回帰テスト

`scripts/test_phase1_safety.mjs`

DBを使わず次を検査する。

1. 走守なしの総合ピークが停止する
2. 明示的な打撃ピークは利用できる
3. 走守がそろった総合ピークは利用できる
4. 走守なしの総合全盛期が停止する
5. 身体能力SQLに`targetSeason + MAX_GAP`が復活していない

実行方法:

```bash
node scripts/test_phase1_safety.mjs
```

## 今回あえて修正していないもの

### 表示走力と内部参照走力の不一致

現行コードでは、表示走力は複数年プール値を使う一方、以下は対象年単年の`sc.score`を使う。

- 盗塁得能
- 走塁得能
- 内野安打得能
- 守備力で差し引く走力

これは次の修正対象である。最終的な共通値を`speed_z_final`として一本化し、各残差計算へ渡す必要がある。

### prime合成の再設計

安全停止のみ。再開条件は次の通り。

- 能力ごとに同じ対象期間を使う
- 環境補正を合成前・合成後のどちらか一度だけにする
- 得能・分割成績の合成ルールを定義する
- 走塁・守備得点を年度選定へ接続する
