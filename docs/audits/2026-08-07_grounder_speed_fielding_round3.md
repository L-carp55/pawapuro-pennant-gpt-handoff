# 内野ゴロイベントによる走力・守備力監査 round 3

日付: 2026-08-07
状態: **走力proxyは小幅改善だがsanity不合格。守備イベント残差はRngRと整合するが年安定性不足。いずれも本番未採用。**

## 目的

既存 `infield_grounder_events`（2020-2026、31,003件）を、内野肩だけでなく走力・守備力の再設計にも使えるか確認した。

オーナー確定の走力sanity check:

```text
周東佑京 > 近本光司 > 源田壮亮
```

守備力は旧 `RngR - E[RngR|speed]` の単純残差定義を撤回済み。
新設計では、反応・一歩目・加速・判断・ポジショニング等を含む守備力と走力が共同でアウト確率を作る。

## 1. 走力: 内野ゴロイベントを追加proxyにできるか

### 1.1 既存3特徴

2026 NPB+最高走行速度98人に対する2023-2025統計proxy:

```text
併殺回避            r ≈ +0.591
UBR/PA              r ≈ +0.621
内野安打/in-play    r ≈ +0.659
```

3特徴Ridge 5-fold CV:

```text
RMSE ≈ 0.868 km/h
Pearson ≈ 0.713
Spearman ≈ 0.729
```

### 1.2 31,003件の内野ゴロから打者側の情報を追加

`out / infield_hit` だけを使い、失策は除外。
まず単純な「内野ゴロのうち内野安打になった割合」を2023-2025で集計した。

直接速度との単独相関は約 +0.40 で、既存NF3の `内野安打/in-play` より弱い。
ただし両者は同一ではなく、Ridgeへ追加するとわずかな独立情報が残った。

探索用Pythonでの5-fold CV:

```text
既存3特徴
RMSE 0.868 / Pearson 0.713 / Spearman 0.729

+ 内野ゴロevent IH率
RMSE 0.860 / Pearson 0.732前後 / Spearman 0.747前後

+ 座標・守備者・球場・年度で期待IH率を調整したevent残差
RMSE 0.856 / Pearson 0.735 / Spearman 0.754
```

一塁到達タイムを目的変数にしても小幅改善した。

### 1.3 ただしsanity checkはまだ不合格

文脈調整event残差を加えた4特徴モデルを、2022-2024本人証拠だけへ適用:

```text
周東  約33.21 km/h
源田  約32.84 km/h
近本  約32.67 km/h
```

旧3特徴の `周東 > 源田 > 近本` より源田-近本差は縮まったが、
**近本 > 源田へは反転しなかった。**

よってevent IH proxyは「追加候補」として残すが、本番走力へはまだ入れない。

### 1.4 併殺機会の分母変更は棄却

NF3 runner splitから「一塁走者がいる打席」を近似し、

```text
-GDP / 一塁走者ありPA
```

を試した。

直接速度との相関:

```text
旧: -GDP / 推定ゴロ数       ≈ +0.591
新: -GDP / 一塁走者ありPA   ≈ +0.381
```

改善しないため不採用。

### 1.5 外部sanityの独立証拠

これは学習ラベルには使わない。

- 近本光司: 2018年社会人時代の実戦で一塁到達3.75秒との報道。
- 源田壮亮: パ・リーグ公式系記事で2021年の内野安打一塁到達3.84秒 / 3.85秒が紹介されている。

年度・打球・計測条件が違うので係数学習には使えないが、
`近本 > 源田` をsanity checkに置くことと矛盾しない。

## 2. 守備力: event-level joint modelの試行

### 2.1 旧式との違い

旧:

```text
RngRを年単位でまとめる
→ 走力との一次回帰を引く
→ 残差を守備力
```

今回:

```text
各ゴロごとに
P(infield hit)
 = f(hc_x, hc_y, 守備位置, 打者, 打席左右, 球場, 年度, 野手走力, 走力×位置)

実際に内野安打を防いだ量 - expected
→ 野手×年のevent残差
```

つまり、走力はプレー単位のアウト確率へ直接入り、打球位置との相互作用も許す。
単純な `RngR - a×speed` ではない。

### 2.2 RngRとの整合

2020-2025内野ゴロを使い、野手×年のevent残差をRngR/1000innと比較。
サンプル下限で多少動くが、全体では概ね:

```text
min 10 events   r ≈ +0.33
min 30 events   r ≈ +0.37
min 50 events   r ≈ +0.43
```

遊撃手では:

```text
min 30 events   r ≈ +0.51
min 50 events   r ≈ +0.51
```

三塁手でも大標本では +0.4〜+0.6程度。
方向としては現実の守備範囲と整合する。

### 2.3 しかし年安定性が不足

同じ選手・同じ位置の隣接年event残差:

```text
min 10 events   r ≈ +0.05〜+0.07
min 20 events   r ≈ 0
min 30 events   r ≈ +0.05〜+0.09
min 50 events   ほぼ0
```

打者を年度別固定効果に変えても大幅改善しない。

したがって、**現テーブルだけで年間守備力を確定するのは禁止。**

## 3. 年安定性が低い原因の有力候補

DELTAの2019遊撃手分析では、守備範囲の分解に以下を使っている。

- ゾーン（打球方向・位置）
- ハングタイム = 打球発生から捕球、または内野通過までの時間
- 速いゴロ / 遅いゴロでアウト難易度が大きく異なる
- 「ゴロへの反応」自体を分析軸にする

一方、現在の `infield_grounder_events` は:

```text
season / park / batter / fielder / pos / hc_x / hc_y / outcome
```

まではあるが、**ハングタイム・打球速度・初期守備位置を持たない。**

元PBPビルダーも確認したが、現状利用している列にそれらは無い。
この欠損が、同じ座標でも難易度の違う打球を一緒にしてしまい、年安定性を落としている可能性が高い。

## 5. 次の工程

### 走力
1. `audit_speed_vs_npbplus.mjs` に内野ゴロevent IH率を正式追加し、Node側でCV再現。
2. event残差版は、最終採用候補になった場合だけNodeへ移植する。
3. 近本-源田を分ける別の直接速度proxyを探索。盗塁企図率は既にオーナー判断で主材料から棄却済み。

### 守備力
1. ハングタイム相当を取得できる別データ源がないか確認。
2. 無ければ `RngR + event residual + 走力` を共同観測としてlatent fieldingを推定するが、年安定性を受入条件にする。
3. `src/engine/fielding_response.mjs` の応答曲面は、較正データが揃うまでフェイルファストを維持。

### 捕球
既存方針どおり、元Claude環境で生PBPから `fielding_error_events` を再生成し、expected-errorへ進む。

### 内野肩
`docs/audits/2026-08-07_infield_arm_proxy_round2.md` の候補C（文脈調整・複数年deep residual）の外部検証拡張を継続する。
