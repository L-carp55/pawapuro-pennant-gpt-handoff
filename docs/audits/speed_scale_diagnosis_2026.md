# 走力 スケール診断 — 自作査定の幅が狭い原因

生成日: 2026-08-13

## 結論

幅が狭い原因は2つあり、**2つ目は配線の不備**である。

### 原因1: 合成zは必ず縮む（統計的な必然）

```text
合成zの標準偏差 = 0.767   （1.0なら母集団の幅を保てている）
```
走力は5材料（三塁打割合・併殺回避・内野安打率・進塁・UBR）の**重み付き平均**。
材料同士が完全相関でない限り、平均すると幅は必ず縮む。
これは推定として正しい（条件付き期待値）が、**能力値としては母集団の幅を再現しない**。

### 原因2: ★その縮みを戻す較正が、ほぼ誰にも掛かっていない

```text
目盛り: center=50 spread=15  → 幅 11.5
較正 slope=1.3811          → 幅 15.9  ← 本来ここまで戻るはず
実際の自作査定の幅                13.3
パワプロ2026の幅                  15.5
```
**較正が掛かった選手は 98 / 98 人しかいない。**

原因: NPB+実測を混ぜる経路（`blendDirect`）が `applyScale` を通らないため。
この設計自体は意図的で、理由も記録されている——NPB+の変換式はパワプロの能力値を
目標に当てはめたものなので、パワプロ由来の較正を再度当てると二重になる、というもの。

**だが混ぜている相手（プレー結果由来の統計値）は較正前の目盛りに乗っている。**
つまり `blendDirect` は**目盛りの違う2つの量を混ぜており**、結果はどちらの目盛りでもない。
これが幅が縮む主因。

### 数値の整合

合成z 0.767 × spread 15 × 較正 1.381 = **15.9**
パワプロの幅 = **15.5**

**較正さえ正しく届いていれば、幅の問題はほぼ解消する計算になる。**
つまりこれはモデルの失敗ではなく、修正が対象へ届いていない配線の問題。

## 材料間の系統的なずれ

```text
NPB+由来 − プレー結果由来 の平均 = -0.5点   (n=97)
同じ向きの選手 = 46 / 97
```
材料衝突の大半もまた目盛りのずれ。**選手固有の衝突は、この系統分を引いた残り**で判定する。

## 未解決

- 較正を混合経路にも掛けるべきかは**二重適用の懸念があるため要設計**。
  正しい形は「NPB+側を統計側の目盛りへ変換してから混ぜる」か、
  「両方を較正後の目盛りへ揃えてから混ぜる」のいずれか。本診断では方針決定まで行わない
- 較正値そのもの（slope 1.3811）は2024年143人でパワプロへ合わせたもの。
  パワプロを目盛りの正本にしない方針と衝突するため、最終的にはアンカーか
  エンジン整合で置き換える必要がある（本工程の範囲外）
