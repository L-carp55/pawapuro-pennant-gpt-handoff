- **★KONAMI（パワプロ）の値を、設計の採否や良し悪しの物差しに使わない**（凍結まで）。
  参考として眺めるのは可。だが「パワプロとの誤差が減った/増えた」を**採用・不採用の理由にしてはいけない**。
  理由は3つ: (1) 2026-07-31オーナー確定でKONAMI比較は参考チェックへ格下げ (2) 仕様05 §10が凍結後の比較を定める
  (3) KONAMIは手査定で方法非公開のため、誤差最小化は**KONAMIの癖の再現**になる。
  **この違反は2026-07-31と2026-08-04の2回起きている**。2回目は、その注意書き（A §14）が載っているこの表を
  編集しながら起きた——**書いてあるだけでは止まらない**。採否を書く時は必ず
  `configs/ratings.json` の `special_abilities.base_reflection._judging_criterion` を先に読む。
  正しい物差しは (a)仕様の設計原則 (b)データが測れているか (c)自作エンジンでの分布一致。
- **他所で確立した規律を流用する時は、その規律の適用範囲を確認する**。
  2026-08-04の違反の直接原因は、「正解ラベルは2系統持つ」（**材料選定**の規律）を
  **設計の採否**へ広げたこと。規律には効く範囲があり、広げると別のルールを踏み抜く。

- ✅の条件は**2つとも**満たすこと: (1) 実データで計算が動く (2) **その値が成果物（カード・レポート）に出ている**。
  片方だけなら🔶。2026-08-01に弾道（§7）と稼働率（§8.2）が「計算は動くがカードに出ていない」まま✅になっており、
  オーナー指摘で発覚した。**計算した値の行き先を決めずに完了と数えない**（内部専用なら本表にそう書く）
- 新しい能力・項目を足す時は、**先に「本家の項目一覧」と突き合わせる**。欠け／余り／置き場所の3方向で見る
  （2026-08-01: 弾道とけがしにくさが欠け、盗塁・走塁が基礎能力の並びに紛れ、肩力が位置ごとに重複していた）

- ⛔（疲労補正・ゴールデングラブ）は仕様が実装を禁止しているので、実装しないことが正しい対応。回帰テストQ10で「GG列があっても結果が変わらない」ことを検証する
- 回帰テストQ1-Q13（E群）は各実装と同時に書く。まとめて後回しにしない
- **件数を書き換える時は行を機械的に数える**（目視で足し引きしない）。2026-08-01に行を1つ足しながら合計を76のままにした
