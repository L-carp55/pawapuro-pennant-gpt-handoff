## 1. ミートとパワーの相互作用

### 1.1 本塁打数はパワーそのものではない

本塁打数は、パワー・ミート・打球角度・打球方向・球場・相手投手・出場機会などが合成された**結果指標**である。

したがって、

```text
HR数 -> パワー
```

を主査定経路にしてはならない。

特に本塁打が少ない選手では、HR数だけからパワーを推定すると分解不能になるため、別経路が必要。

パワーの一次材料は可能な限り以下を優先する。

- EV / Max EV
- Barrel%
- Hard-Hit%
- xSLG
- ISO
- HR/FB
- Launch Angle
- FB%
- 長打の打球内容
- 2B/3B（脚力寄与を分離）

HR数は最終的な整合性チェックとして使う。

### 1.2 低HR選手のパワー

低HRは必ずしも低パワーを意味しない。

以下を分離して評価する。

- 強い打球を作る能力
- フライを作る能力
- ボールへ当てる能力
- 出場機会
- 球場
- 相手投手

低HR選手でもMax EVやHard-Hit、ISO等が高ければ、HR数だけを理由にパワーを過度に下げない。

### 1.3 ミート→パワー、パワー→ミートの二重弱体化を禁止

高パワーは同じコンタクト能力でも打率を押し上げうる。
高ミートは同じ打球強度でもHR/長打結果を増やしうる。

この相互作用をミートとパワーの両方から同時に差し引くと、同じ現象を二重控除して両能力を過小評価する。

したがって処理順序を固定する。

```text
1. ミートを先に決める
2. そのミートを固定する
3. パワーを決める
```

### 1.4 ミート査定の順序

補正打率等から平均得能込みミートを作る際、同打率を生んだパワー寄与を分離する。

方向:

```text
高パワーで同打率 -> 純粋ミートは少し低い
低パワーで同打率 -> 純粋ミートは少し高い
```

この段階でミートを凍結する。

### 1.5 パワー査定の順序

凍結済みミートを条件として、打球強度・角度・長打生成能力を評価する。

高ミートによってHR/長打結果が増えている分をパワーへ二重計上しない。
ただしミート側で既に行った補正を再度パワー側でも同じ意味で差し引かない。

具体係数はOPEN。シミュレーションまたは実測データで校正するまで恣意的な相互減点を置かない。

## 2. 走力の現在定義

### 2.1 定義

走力は、

> **最初の走行ステップを起点として、野球で頻出する90ft（27.43m）前後を直線的に速く移動する身体能力**

とする。

含む:

- 初期加速
- 10m/20m/30m付近までの加速
- top-end speed
- 約90ftまでの速度維持

基礎走力から除外:

- 盗塁リード
- 投手の癖読み
- 盗塁スタート判断
- スライディング
- ベースランニング判断
- 打席から走行への移行技術
- セーフティーバント特有の開始条件
- 内野安打結果
- UBR/BsR
- 守備反応・ルート判断

走力と盗塁・走塁技術は完全に分離する。

## 3. 走力証拠の優先順位

現時点の優先順位:

1. **cleanな直接T90 / 90ft**
2. **cleanなT30/T10等の同時短距離split**
3. **同一条件で標準化された電子/光電管50m等**
4. **NPB+ Sprint Speed** — 現状はprovisional baseline
5. **方式不明・古い30m/50m** — profileの方向判断のみ
6. **Home-to-first / 一塁到達** — CONTEXT_ONLY
7. **スカウティング・SNS・映像の相対評価** — ordinal QA / 補完

### 3.1 50mの扱い

50mタイムを距離比で27.43mへ直接変換してはならない。

標準化電子計時で同一集団内順位が得られる場合のみ、短距離加速priorとして使用可能。
方式不明、手動、特殊スタート、古いプロフィール値は現在T90へ直接数値変換しない。

### 3.2 Home-to-firstの扱い

一塁到達は、

- 左右打席
- スイング後姿勢
- 打球確認
- バント
- ヘッドスライディング
- 時計開始点

が混ざるため、純粋T90の直接入力にしない。

ただしSprint Speed由来値が明らかに不自然かを確認するQA材料としては有用。

## 4. MLB検証とNPB+ transfer boundary

MLB 2017-2025では、Sprint Speed単独よりT10/T30を加えた方がT90予測が明確に改善した。

したがって、

> **走力 = top speedだけではなく加速を含む**

という構造は採用する。

一方、NPB+ Sprint SpeedとMLB Statcast Sprint Speedは名称が同じでも数値定義の同一性が確認できていない。

禁止:

- MLB係数を単位換算してNPB+へ移植
- MLB MAEをNPB+の誤差としてそのまま使用
- NPB+ Sprint Speedを確定T90とみなす

NPB+→T90 bridgeは未較正のまま扱う。

## 5. 小標本・出場機会不足

少出場選手では、Sprint Speedが低いことが能力低下ではなく、**最大努力走行をまだ観測できていない**可能性がある。

優先して確認する情報:

1. Sprint Speed対象走行数 / qualified run count
2. 最大努力走行になり得るイベント数
3. PA
4. 出場試合数

サンプル数が少ない場合、Sprint Speed低値だけを理由に大幅下方査定しない。

特に、

```text
NPB+ Sprint Speed由来査定 << 過去身体データ / 長期評価
かつ
2026出場量が少ない
```

場合は、`LOW_EXPOSURE_SPRINT_UNDERSAMPLING`候補として信頼度を下げる。

固定PA閾値は現時点で置かない。今後の100選手データで校正する。

## 6. 古い身体測定の時間補正

古いT90/30m/50mは年数差だけで機械的に無効化しない。

後続QAとして、

- 年齢
- 故障
- 出場量
- 過去年Sprint Speed/T90
- 当時→現在のPowerPro走力推移
- MLB選手ではThe Show Speed推移

を参照する。

ただしPowerPro/The Showの変化量を物理能力の減衰係数として直接使用しない。
あくまで古い身体証拠を現在へどの程度持ち越してよいかの**時間軸QA**とする。

## 7. 高信頼アンカー＋相対比較

すべての選手を同一の不完全な式へ押し込まない。

まず2015-2026等の過去選手も含め、以下を満たす高信頼アンカーを能力帯ごとに多数作る。

- 身体データが十分
- 計測条件が比較的明確
- 出場量が十分
- 時系列変化を説明可能
- 複数証拠が大きく矛盾しない
- 独立査定に納得できる

データ不足選手は、アンカーとのpairwise/ordinal比較で補完する。

例:

```text
A(75)より明らかに遅い
B(55)より明らかに速い
C(65)と同程度
-> 60-67程度の候補レンジ
```

この方法は、精密に見える根拠薄弱な一点推定より優先する。

## 8. SNSコンセンサスと映像評価

全選手を個別に映像監査する必要はない。
多数のファンが長期間試合映像を見た結果としての**集合的相対評価**を、映像評価のproxyとして使用してよい。

主用途:

- 明らかな俊足/鈍足の外れ値検出
- AとBのどちらが速いかという相対順位
- top-speed型 / acceleration型の示唆
- 公式査定への広範な違和感の確認

### 8.1 SNS証拠Tier

**SNS-A**
- 複数年
- 多数の独立投稿
- 他選手との具体的比較あり
- 実際の試合場面に基づく
- 方向がほぼ一致

**SNS-B**
- 複数独立投稿で方向一致

**SNS-C**
- 少数だが具体的場面あり。QAのみ

**SNS-D / 使用禁止**
- 単なるミーム
- 一件の珍プレー
- 同一投稿の転載
- PowerPro能力を根拠にした「足が速い/遅い」
- 盗塁の上手さを純粋速度と混同

SNSは絶対点を直接付けるより、アンカー間の順位制約として使う。

直接映像確認は、物理データ・アンカー・SNSが矛盾するケースのtie-breakerに限定してよい。

## 9. PowerPro / MLB The Showの扱い

### 9.1 PowerPro

PowerProは独立査定を凍結した後の外部QA。

用途:

- 時系列変化
- 査定変更のタイミング
- 過去身体測定を現在へ持ち越す際の補助
- 大きな乖離の原因分析

禁止:

- PowerPro値に合わせて係数をfit
- 差をそのまま補正量にする

### 9.2 MLB The Show

The Showは、MLB実測の変化をゲーム査定がどう追随するかを見る外部QAとして使用する。

将来の再利用のため、SpeedだけでなくLive Rosterの以下も可能な限り長期保存する。

- Speed
- Stealing
- Baserunning Aggressiveness
- Arm Strength
- Arm Accuracy
- Fielding
- Reaction
- Blocking
- その他取得可能なraw attributes

Diamond Dynasty特殊カードは通常査定研究から除外する。

The Show属性がStatcast等を基にしている場合、実測と独立した第二証拠として二重カウントしない。

## 10. 人間補正のルール

禁止:

- 「パワプロが80だから80付近へ上げる」
- 方式不明50mを理由に隣接ランク境界へ機械的に移動
- owner feelを教師値にして係数をfit

許可:

- 高信頼アンカーで挟む
- 複数独立証拠が同方向なら候補レンジを移動
- SNS-A/Bで明らかな順位矛盾を修正
- 必要な場合だけ映像tie-break

結果は一点が不適切ならレンジを保持する。

## 11. 大規模調査の委任原則

多数選手・多数年度・多数ソースのread-heavy作業はCodexへ委任する。

大規模タスクでは、プロンプトに**サブエージェントによる並列実行を明示**する。

原則:

- 年代別/球団別/ソース別に独立Agentへ分割
- QA Agentを別に置く
- 各Agentは別中間ファイルへ出力
- 同一ファイルを複数Agentで同時編集しない
- 親Agentだけが最終統合
- 独立taskは別branch/worktreeで並列実行

ブラウザGPT側は、収集結果の設計・統計分析・矛盾解消・最終査定を担当する。

## 12. 現在の査定フロー

### 打撃

```text
環境/サンプル補正
-> ミート推定
-> パワー寄与をミートから分離
-> ミート凍結
-> 打球強度/角度/長打生成能力からパワー推定
-> 固定済みミートによる結果寄与を整理
-> HR等の結果で整合性QA
```

### 走力

```text
直接T90/T30/T10
-> 標準化電子短距離
-> NPB+ Sprint Speed provisional baseline
-> historical profile
-> exposure / temporal QA
-> 高信頼アンカーとの相対比較
-> SNSコンセンサス
-> 必要時のみ映像tie-break
-> 最終点またはレンジ
-> PowerPro/The Show比較は最後
```
