# 得能・金特・KONAMI比較仕様

---

## 1. 得能の役割

得能は「選手の特徴を追加する飾り」ではなく、総成績を平常時能力へ分解するための要素。

```text
総成績
= 基礎能力
+ チャンス
+ 対左
+ 三振
+ AH/PH
+ 打球方向
+ 走力・内野安打
+ その他
```

同じ効果を基礎能力と得能に重ねない。

---

## 2. 平均得能込み基準

ミート・パワーのアンカーは、同成績帯に平均的な得能が付く前提。

したがって:

```text
得能が平均より多い → 基礎能力を下げる
得能が平均より少ない → 基礎能力を上げる
```

ただし得能の点数寄与は未校正。過去の+5〜7等は仮説であり確定値ではない。

---

## 3. チャンス

基本:

```text
DeltaChance = AVG_RISP - AVG_nonRISP
```

注意:

- 単年ブレが大きい。
- H/ABを使って多年度へ縮小。
- RBIは直接使わない。

打点が高い場合に調べるもの:

- 満塁成績
- サヨナラ機会
- 終盤同点/僅差
- ビハインド時
- 犠飛
- HRの走者状況
- 打順・前走者出塁率

---

## 4. 対左

```text
DeltaLeft = AVG_vsL - AVG_vsR
```

ミート差と長打差を分ける。

- 打率差 → 対左ミート系
- HR/ISO差 → 対左パワー効果
- サンプルは多年度へ回帰

---

## 5. 三振

現行方針:

- 三振赤特を付ける場合、基礎ミートを少し戻す。
- 大幅に戻さない。
- K%を別にミートへ強く減点しない。
- ゲーム内効果の校正が必要。

過去のエルドレッド・バティスタ査定では、戻し幅とチャンス/対左調整が一貫していなかったため廃版。

---

## 6. 高パワー・低パワーとミート

方向:

```text
同打率・高P → Mを少し下げる
同打率・低P → Mを少し上げる
```

理由:

ゲーム内でパワーが安打生成・長打化へ影響するため。

点数は実験で求める。

実験例:

```text
同じ相手・球場・打席数で
Mを固定しPだけ変える
→ 打率・BABIP・HR・SLGを計測
```

---

## 7. 内野安打

内野安打数を全てミートに入れない。

```text
内野安打寄与
→ 走力
→ 内野安打○
→ 左打席・ゴロ傾向
```

ただしコンタクトしてゴロを作る能力もあるため、ゼロ扱いにもせずゲーム内校正する。

---

## 8. 青得能・赤得能の根拠台帳

各得能に:

```yaml
ability:
rank:
stat_definition:
sample:
season_value:
league_value:
multi_year_prior:
confidence:
source:
already_reflected_in_base:
```

を保存。

`already_reflected_in_base=true`なら、能力値側で再調整しない。

---

## 9. 金特 — ADOPTED

金特は歴史的レベルのみ。

条件候補:

- 日本記録・世界記録級
- 歴代上位0.5%級
- 複数年で歴史的水準
- 単年でも明確な歴史的記録
- ゲーム内で通常青特では再現不能

禁止:

- MVPだから
- タイトルを取ったから
- 有名だから
- 「候補」として広く付ける

2017 WBC全盛期査定でも、通常は青特まで。金特は個別に歴史的根拠を示す。

---

## 10. KONAMI比較 — Blind Freeze

### 10.1 比較前

1. 入力データを固定。
2. 独自査定を完了。
3. 得能を確定。
4. 計算ログを保存。
5. Git commitまたはSHA256で凍結。

### 10.2 比較データ

```text
作品
プラットフォーム
アップデート日
開幕版/決定版
査定対象期間
基礎能力
全得能
サブポジ
ケガしにくさ
調子安定/極端
```

### 10.3 比較単位

- 基礎能力差
- 得能差
- 実効能力差
- データ時点差
- キャラクター表現差
- 査定ノイズ

### 10.4 禁止

KONAMI能力を先に見て独自値を合わせる。

## 11. 野間2018の教訓

KONAMIの野間を、ミートB71だけで評価してはいけない。

得能:

```text
チャンスF
対左F
内野安打○
走塁A
```

等とのセットで実効打率を見る必要がある。

このケースはKONAMI比較の回帰テストに使う。
