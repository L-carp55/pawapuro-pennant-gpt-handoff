## 0. 設計の骨子（1段落）

走力がパワプロへ引き寄せられ続ける真因は、PowerProが強いからではなく、
**走力に目盛りの正本（アンカー）が無いから**である。パワー/ミートにはオーナーが裁定した
目安表があり、だから2026-08-06に「パワプロがアンカーを上書きしている」と検出できた。
走力にはそれが無いので、同じことが起きても誰も気づけない。
したがってv2は **①走力アンカーをオーナー裁定で新設 → ②既存の較正済み統計モデルを骨格として
そのアンカー上へ載せる → ③物理実測・SNS・PowerProは骨格を「更新」するだけで上書きしない**
という順序にする。PowerProはpriorではなく**QAとstale検出**へ戻す。

## 3. [0] 走力アンカーの作り方（最優先・オーナー作業）

パワーの前例をそのまま使う。パワーは「本塁打◯本 → ◯点」で、オーナーは
「山川2024（換算45.6本）の89.8は得能込みとして妥当」と個票で裁定できた。

走力で同じことをするには2系統ある。**両方あると最善だが、Bだけでも成立する。**

### A. 物理アンカー（T90秒 → 点）

```text
（数値はすべてオーナー裁定が必要な仮置き。CCが勝手に決めない）
  T90 3.85秒 → 90
  T90 4.00秒 → 80
  T90 4.15秒 → 70
  T90 4.30秒 → 60
  T90 4.50秒 → 45
```

**制約**: 現在の current physical measurement は実質モンテロ2024の1件のみ。
したがってAだけでは選手を載せられない。**Aは目盛りの定義に使い、載せるのはBと[1]で行う。**

### B. 代表選手アンカー（オーナーが点数を裁定）

能力帯を跨いで10〜15人程度、オーナーが「この選手はだいたい◯点」を決める。
選定はCCが提案し、**オーナーが数値を入れる**。候補の性質:

- 明確な俊足（例: 周東佑京）
- 中の上 / 平均 / 中の下
- 明確な鈍足
- **物理実測がある選手を優先**（モンテロ・筒香・カリステ・秋山・ポランコ・サンタナ・林・友杉・奈良間）
- **オーナーが実際に試合を見て確信がある選手**

これがパワーの `power_anchors` と同じ役割を果たす正本になる。

### なぜこれが循環を断つか

アンカーが正本になると、以後どの経路（PowerPro分布合わせ・実測変換・SNS）が入っても、
**「アンカーの各点がこの変換後も生き残るか」で機械的に検査できる**。
2026-08-06にパワーで使った検出法がそのまま走力にも使える。

## 4. [1] 骨格に既存統計モデルを使う根拠

- 材料の重みは**すべて翌年再現性の実測値**（0.445〜0.695）。恣意的な係数が無い
- **5年プール**なので2026年の打撃データが無くても（`v_batting`は2025年まで）
  2021-2025で2026の骨格を作れる
- 脚力と走塁技術の分離が**既に実装済み**（`advanceOnSpeed` / `ubrOnSpeed` による残差）
- 全選手・全年に適用できる＝R-5（目盛り整合）を自動的に満たす

### 骨格に対して必ず行うこと

1. **アンカーへの再較正**: 現在の `scale_calibration.走力`（slope 1.3811 / intercept -4.3301）は
   **パワプロ143人の分布へ合わせたもの**。アンカーが出来たら**これを破棄し、アンカーへ当てはめ直す**。
   （パワー/ミートで2026-08-06に行った処置と同じ）
2. **controlとしての性能記録**: 新方式を評価するとき、**必ずこの骨格をbaselineに置く**。
   GPTの15ブランチはこれをやっていない（R-4）

## 5. [2] 実測の混ぜ方 — 上書き禁止・MAEで重みを決める

既存の `blendDirect` の形式を維持する（重み＝ホールドアウト精度）。
**重みは相関でなくMAEから決める**（R-4、H2Fの相関0.59/MAE12.9の教訓）。

| 材料 | 現状の実測 | v2での扱い |
|---|---|---|
| direct T90 / 標準化電子短距離 | 件数が極少（current実質1件） | あれば最優先。ただし**件数が少ないことを重みに反映** |
| NPB+ top speed | test_r 0.762 / **test_mae 10.55** / test_n 14 | 中〜低重み。**単独主軸にしない** |
| 調整済みH2F | test_r 0.588 / **test_mae 12.90** / test_n 14 | **現状の精度では点数へ入れない**。左右打席・バント・本数を調整して**MAEが改善したら**入れる |

### NPB+→T90 bridge の可否判定（先にやる）

原則§4は「NPB+ Sprint Speedを確定T90とみなす」ことを禁じている。
NPB+を軸に据えるなら、NPB+とdirect T90が両方ある選手でbridgeを較正する必要がある。
**現状その母数が足りないなら「NPB+は軸にできない」と結論して記録する**（R-11）。
これは失敗ではなく、探索の結果として明示すべき negative finding。

## 6. [3] 人間・集合知 — 点数を作らせない

- **SNS Physical Observation Consensus**: 「AよりBが速い」という**順位制約**として使う。
  絶対点を動かさない。アンカー間の矛盾検出に限定（原則§8「アンカー間の順位制約として使う」を維持）
- **owner verdict**: 個票単位では最終権限。ただし**係数の較正に使わない**
  （原則§10「owner feelを教師値にして係数をfitするのは禁止」）。
  この境界を実装で担保する＝verdictは選手個別の上書き値として保存し、
  回帰・重み推定の入力配列には入れない
- **owner verdictの保護**: 後工程がverdictを上書きしないよう、
  verdictを持つ選手には `owner_locked: true` を立て、
  以後の自動処理はこの選手の値を変更できない（変更しようとしたら失敗させる）

## 7. [4] PowerProの正しい使い方 — QAとstale検出

PowerProは**入力に入れない**。用途を3つに限定する。

1. **乖離の原因分析**: 差が大きい選手を「なぜ違うか」の調査対象として抽出
2. **stale/inertia検出**: long panel（23,206観測 / 2,972 ID / 58版）を使い、
   「3年以上据え置き」「major injury後も据え置き」「Prospiだけ低下」を機械検出。
   **これはPowerProの信頼性を測る作業であって、こちらの査定を動かす作業ではない**
3. **時間軸QA**: 古い身体測定を現在へどれだけ持ち越すかの補助（原則§6の用途に限定）

### SNS Rating Consensus の置き場所（R-7の修正）

「PowerProの査定が妥当か」という意見は**走力の証拠ではない**。
→ **stale detectorの材料**に置く。gap audit §3.3 の使い方が正しく、
§5-B の入力リストに入れているのが不整合。**入力から外す。**

## 8. [5] 検証設計 — 入力に使ったもので検証しない

### 一次指標（合否を決める）

**V1. 時間ホールドアウト**
2021-2024の材料だけで査定を作り、**2025の実プレー結果**を予測する:
- 三塁打割合
- 内野安打率
- 進塁成功（1球データ由来 `advance`）
- GIDP回避

走力は「速い人は速い結果を出す」という検証可能な帰結を持つ**唯一の能力**なので、
この検証が成立する。走力査定の質を、パワプロを一切見ずに測れる。

**V2. エンジン整合（プロジェクトの正式な合否基準）**
12球団×143試合を回し、**盗塁数・三塁打数・内野安打数**のリーグ分布が実データと一致するか。
→ ここで100人と非100人の目盛りが揃っていないと評価不能になる（R-5）。

### 参考指標（合否に使わない）

- PowerPro一致率（MAE / within-5 / correlation）
- owner plausibility
- community consensus

**これらは「入力に使ったもの」または「同化を招くもの」なので、一次指標にしない。**

## 9. 二重計上の防止（R-6）

`advance`（1球データ由来の進塁）は**既に走力の材料**であり、
**その残差**が走塁得能になっている。

Tier F に "extra-base advancement" を再投入する場合は、
**既存の `advance` と同一物でないことを先に示す**。示せないなら入れない。

同様に:
- `infieldHit` は既に走力材料 → Tier F の "infield-hit tendency" と重複
- `gdpAvoid` は既に走力材料 → Tier F の "GIDP avoidance" と重複
- `triple` は既に走力材料 → Tier F の "triples" と重複

**Tier Fの4項目のうち3項目は既存材料と同一。** 新規に足せるのは
pinch-runner usage と base-to-base 程度で、これらは**別物であることの立証が先**。

## 11. この提案が抱えるリスク（自己申告）

- **アンカーをオーナーが決められない可能性**: 走力は本塁打数のような直観的な単位が無い。
  その場合、代表選手アンカー（§3-B）だけで進める。それも難しければ、
  **アンカー無しであることを明示的な既知の弱点として記録**し、
  パワプロ同化の検出器が働かないことを受け入れた上で進む（推奨しない）
- **既存統計モデル自体の欠陥は本監査で検証していない**。自作物の自己レビューは
  一方向に甘いため、骨格の性能はV1で外部から測る必要がある
- **Codexの15ブランチを直接読んでいない**。RETAIN判定は自己申告ベース（監査§5参照）
