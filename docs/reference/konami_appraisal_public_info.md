# KONAMIの査定方法について公開されている情報

> オーナーが2026-08-01に「あくまで参考として」提供。一次情報は末尾の出典。
> **本プロジェクトの査定はKONAMI再現を目的にしていない**（照準は自作エンジン整合、CLAUDE.md参照）が、
> 走力・肩力が実感と合わない原因の診断として直接効くため参照資料として保存する。

## 1. KONAMIの査定は数式だけではない

公開情報から読み取れる流れ:

1. **成績データを取得** — 外部のデータ提供会社（共同通信デジタル／Japan Baseball Data）から取得し、独自システムでゲーム能力へ変換。セイバーメトリクスも考慮
2. **球団別担当者が映像を確認** — 一軍だけでなくファームも。新人はアマチュア時代の映像をコマ送りで確認することもある
3. **査定会議と統括担当による横断調整** — 担当者ごとの基準差をリーグ全体で揃える
4. **ペナントを回して検証** — 設定した能力で何度もシミュレーションし、現実離れした結果にならないよう調整

**具体的な換算式や「50m走○秒なら走力○」という対応表は非公開。**

## 2. 走力・肩力は他の能力と扱いが違う

公式インタビューの記述:

> ミートや守備力など技術系は慎重に評価する一方、**肩の力や足の速さは身体能力をそのまま数値化することが多い**

つまり **走力と肩力は、打撃成績や守備成績よりも身体能力そのものを重視している**。

### 公式ヘルプの定義

| 能力 | 定義 |
|---|---|
| 走力 | **走塁時と守備時の移動速度**に影響する能力 |
| 肩力 | **送球の速さ**に関する能力。外野手では**遠投可能距離**にも影響 |
| 守備力 | 捕球から送球までの速さ、送球の正確性にも影響。**守備範囲は守備力と走力の両方が影響** |

## 3. 本プロジェクトの症状と一致する診断

提供資料が挙げる「走力・肩力だけが不自然に低く出るシステムの設計ミス」:

**走力**
- 盗塁数を重くしすぎている
- **最高速度ではなく盗塁成功率を主入力にしている**
- 守備指標の低下を走力にも反映している
- 年齢による減衰を二重にかけている

**肩力**
- **補殺数を主入力にしている** ← 本プロジェクトが該当
- **守備指標のArm Runsだけで決めている** ← 本プロジェクトが該当
- 送球精度の悪さを肩力から減点している
- 捕球から送球までの遅さを肩力へ混入している
- 外野守備機会の少なさを能力不足と判断している

そして結論:

> **盗塁数・補殺数・UZRなどから直接算出する方式では、かなり低く出やすくなります**
>
> 走力と肩力を再現するには、成績からの回帰モデルだけでなく、**身体能力の独立評価層**を設ける必要があります

これは §16 で独立に到達した結論（「能力そのものと発揮結果は別の量」）と一致し、
`src/ratings/scouting_input.mjs`（第2階層の評価を受け取る経路）の設計を裏づける。

## 4. 補殺の位置づけ（要修正点）

> 補殺数は肩力の直接指標としては弱い。**強肩選手は走者が最初から進塁を控えるため、むしろ補殺機会が減る**。
> また補殺には捕球位置、中継、走者判断、試合状況が影響する。
> したがって補殺は、**肩力の証拠というより、映像評価を補強する情報**として使う方が適切。

本プロジェクトは補殺をARMと並ぶ**主材料の1つ**にしている（§14）。
上記に従えば**補助へ格下げ**すべき。ただし本プロジェクトには映像評価が無いため、
格下げすると肩力の材料が実質ARMだけになる。**スカウティング評価が入るまでは現行維持**とし、
評価が入った選手は評価を主とする（実装済みの動作と一致）。

## 5. 材料の優先順位（提供資料の推定。KONAMI公式の順ではない）

### 走力

| 優先度 | 情報 |
|---|---|
| 高 | 試合映像での実際の加速・最高速度 |
| 高 | 一塁到達タイム、塁間タイム |
| 高 | 球団・報道・スカウトによる50m走評価（新人や出場の少ない選手） |
| 中 | 内野安打、併殺回避、三塁打（実戦速度の裏付け） |
| 中 | 守備時の追走速度 |
| 低〜中 | 盗塁数・成功率（走力ではなく盗塁能力との分離が必要） |
| 低 | 守備指標（守備力・ポジショニングの影響が大きい） |

**50m走は手動計測・測定条件・自己申告の差が大きく、絶対基準にはしにくい**（参考値）。

### 肩力（外野手）

1. 送球速度
2. 遠投能力
3. 深い位置からの送球の強さ
4. ワンバウンド／ノーバウンドで届く距離
5. 映像上の球筋
6. 補殺や進塁抑止（**補助**）

### 肩力（捕手）— 3つを分離する

- **肩力** = 送球球速
- **守備力・捕手技術** = 捕球からリリースまで
- **送球精度** = 二塁ベース付近へ投げられるか

ポップタイムは「捕球→持ち替え→リリース」＋「送球の飛行時間」で構成されるので、
**ポップタイムが速い捕手をそのまま肩力Aとするのは不適切**。

## 6. 盗塁と走力の分離（本プロジェクトの判断を裏づける）

盗塁が少ない理由には、スタートが苦手／投手の癖を盗むのが苦手／サインが出ない／
打順や後続打者との関係／ケガを避けている／チーム方針、などがある。

したがって次の査定が成立する:

- 速いが盗塁しない選手 → **走力：高い／盗塁：D-E／走塁：通常〜高い**
- 足は最上位でないがスタートと技術に優れる → **走力：B／盗塁：A**

2026-08-01にオーナーが盗塁企図率の採用を棄却した根拠（「丸のように走力が高くても
全然盗塁自体を仕掛けないタイプもいる」）と一致する。

## 7. パワプロとプロスピの関係

査定思想（成績データ／映像確認／球団担当制／全体調整／将来予測）は共通と考えられるが、
**同じ基礎値をそのまま移植しているとは公表されていない**。
ゲームエンジンが違うため、タイトルごとのバランスに合わせて再調整される可能性がある。

## 本プロジェクトへの含意

1. **統計だけから走力・肩力を作るのは、KONAMI自身もやっていない**。相関分析（`analyze_pawapuro_anchors.mjs`）で
   「どの統計も弱い相関しかない」という結果が出たら、それは失敗ではなく**この構造の確認**になる
2. **身体能力の独立評価層は必須**。実装済みの `scouting_input.mjs` がその層に当たる
3. **補殺は主材料でなく補助**。格下げの判断はスカウティング評価の充足度と合わせて行う
4. **守備範囲を走力に混ぜない**。公式も「守備範囲＝守備力＋走力の合成」と言っており、
   守備範囲から走力を決めると打球判断やポジショニングまで走力に混入する
   （本プロジェクトは逆方向＝走力で守備範囲を補正しており、この点は整合している）

## ★ 鈴木誠也での検算（本プロジェクトが持っている実測値と突き合わせる）

§17でWeb調査により判明していた値（週刊ベースボール、ドラフト時）:
**遠投115m ／ 50m走5秒8 ／ 投手として147-148km/h**

これを上の表に当てはめると:

| 項目 | 実測 | 換算表 | オーナーの評価 | 差 |
|---|---|---|---|---|
| 肩力 | 遠投115m | **B（70-79）** | **80後半〜90前半** | 換算表の方が**低い** |
| 走力 | 50m走5.8秒 | **A（80-89）**（Wiki）／A-B境界（東海） | **C〜B（60-79）** | 換算表の方が**高い** |

**両方向にずれている**のが重要。単純な「オーナー評価が正しく統計が低い」という話ではない。

考えられる理由:
- **ドラフト時＝高校時代の値**。プロ入り後に肩は伸び、脚は落ちる（年齢）のが自然
- 遠投距離とプロでの**送球速度は別物**。鈴木は投手として147-148km/hを投げており、
  球速ベースなら遠投115mより高く評価される
- 50m走の公称値は「盛られている」可能性を査定者自身が指摘している

→ **プロ入り後の実測値を探す価値がある**（未調査）。

## 査定の3方式（本プロジェクトの位置づけが決まる）

コミュニティの査定Wikiは査定思想を3つに分類している:

| 方式 | 内容 | 使いどころ |
|---|---|---|
| **実能力型** | 50m走・遠投・映像をそのまま評価 | 身体能力の推定 |
| **KONAMI再現型** | 「公式なら何点にするか」を推測 | パワプロらしい分布の再現 |
| **成績再現型** | ペナント結果が現実に近づくよう調整 | ゲーム内出力の校正 |

**同じ選手でも方式が違えば能力値が違って当然**。

本プロジェクトのCLAUDE.mdは照準を「**自作エンジン整合**」（能力→成績の変換をこちらで定義し、
査定はその逆算）と定めており、これは**成績再現型**に当たる。
オーナーが「パワプロの値を見て調整」と言ったのは、ここに**KONAMI再現型と実能力型の要素を足す**という意味。
3方式を混ぜる場合、どの値がどの方式から来たかを分けて持つ必要がある。

## 走力・肩力の組み立て方（提供元の推奨）

### 走力

- **身体能力の事前値**: 実測Sprint Speed／一塁到達／ベースランニング／50m走／スカウト評・映像
- **実戦による確認**: 内野安打／三塁打／盗塁企図／UBR・走塁指標／守備時の追走速度
- **分離するもの**: 盗塁スタート→盗塁能力／ベースランニング判断→走塁能力／打球判断・初動→守備力／打ってからの加速→内野安打○

### 肩力

- **身体能力の事前値**: 送球速度／遠投距離／映像上の球威／スカウト評
- **実戦による確認**: 外野ARM／進塁抑止／補殺／深い位置からの送球／捕手の送球飛行時間
- **分離するもの**: 捕球からリリースまで→守備力／送球精度→送球能力・捕球／低い軌道→レーザービーム／捕手の盗塁阻止率→肩力＋動作＋投手クイック

**順序が重要**: 走力は「盗塁数ではなく純粋なスピードを先に決める」、
肩力は「補殺数ではなく送球そのものの強さを先に決める」。
本プロジェクトは**逆の順序**（成果指標から作り、身体能力の層が後付け）になっている。

## 追加の実務ルール

- **走力と肩力は、重大な故障がない限り単年成績で急落させない**
  → §14で実装した多年推定（振れ幅12点→1点）と一致
- **走力を上げて「走塁」の特殊能力を下げる調整**で守備範囲との兼ね合いを取る例がある
- 右翼手は強肩選手が起用されやすいという**ポジション情報からの補正**の例がある
  → §14で実装した内野手の位置別事前値と同じ考え方
